本轮针对三条反馈：导出图里深色区块的字看不见、想要一套终末地风味的新主题、以及各主题的
悬停状态分不出层级。下面按「改了什么 / 为什么 / 边界在哪」记录，方便下次接手时不踩同一个坑。

## 1 · 导出图里「托管天数」看不见（真 bug）

**现象**：每日汇报选深色信息栏的主题（科研档案 / 工业仪器 / 斜切海报 / 都市拼贴），
导出的 PNG 里「托管：第 1 / 32 天（日期）」几乎与底色同色。

**根因**：`prepareExport()` 会把 `<input>` 换成 `<span>`（html2canvas 不按浏览器方式
绘制控件文字），但替代用的 span 写死了 `background:#fff`，并且**没有设置 color** ——
于是继承了深色信息栏的浅色文字（`--rt-meta-fg`）：白底 + 近白字。

**修法**：新增 `fieldStyle(el, extra)`，从原控件的计算样式里取
`color / background-color / border-color / font-*` 写到替代 span 上，
导出图与屏幕所见一致（浅底深字，或深底浅字）。`select` 的替代元素同样走这条。

**回归断言**：`tests/report-themes.test.mjs` 里「导出同时带上主题与背景」一节。

## 5 · 悬停语言（`hover-states.css`）

问题不在「没有 hover」，而在三处：行 hover 时行内按钮仍用正文色（深底深图标）、
按钮自己的 hover 用了与行底相同的填充（按上去消失）、chip 的 hover 与 active 同样强。

统一成每套主题六个变量（`--hv-fill / --hv-ink / --hv-soft / --hv-line /
--hv-row / --hv-row-ink`），并给出**强对比 + 各自造型**：

- 孤星：铭牌压入 —— 整块反相 + 左缘工业橙状态条；
- P3R：海报斜切 —— 反相色块从左侧擦入，右下角切掉一块；
- 终末地：工作台 —— 强调色从左擦入 + 切角描边。

行内按钮的规则按 `:hover:not(.selected)` 分层，保证「行底色 / 按钮填充」永远不同色。

## 6 · 侧栏主题快捷切换浮层（App.vue）

## 10 · 「代肝代办没有，每日汇报还有」的幽灵托管（真 bug）

**现象**：早期数据与后期数据冲突后出现两条同客户同服务、天数不同的托管；删掉一条之后
「代肝代办」里没有了，但「每日汇报」的托管下拉里还在，怎么点都没反应。

**根因**：`ReportSheet` 里的托管列表是 setup 时的一次性快照：

```js
const hostingTasks = ref(loadHostingTasks())   // ← 只在 setup 跑一次
```

而每日汇报页是**常驻渲染**（`App.vue` 里 `<ReportPage v-show="activeTab === 'report'" />`），
所以项目被删掉后这个 ref 仍持有旧数组 → 下拉里留着一条已经不存在的托管。
`selectedTask` 在这种状态下永远匹配不到项目，确认 / 备注 / 资源回填全部失效
（看起来就是「无法控制」）。

**修法**：

1. 托管列表改成 `computed(() => loadHostingTasks(todayRef.value))`，直接跟随
   `projectsRepo.state`：项目一删，下拉立刻少一项。
2. `todayRef` 只负责「跨天」——`refreshHosting()`（ReportPage 切回本页时调用）刷新它，
   昨天已确认的项目今天重新出现，对外接口不变。
3. 新增 `watch(hostingOptions, …)`：选中的项目被删除或不再生效时清空选择，
   工具栏不会停在一条已经不存在的项目上。

## 10.1 · 「没有记录可删」的那条僵尸记录

还有第二层原因：**两边的过滤口径不一样**。

| 位置 | 过滤条件 |
| --- | --- |
| 代肝代办列表 | `status !== 0 && !isClosed(r)` —— 已完成 / 已归档 / 已取消都**不显示** |
| 每日汇报下拉（修前） | `isHosting(r) && !r.locked` —— **不看 status、也不看是否已结束** |

所以一条 `status === 0`（或已归档 / 已取消）的托管：在「代肝代办」里看不到，
在日报下拉里却还在 —— 用户自然「找不到能删的那条」。

**修法**：

1. `loadHostingTasks()` 与代肝代办同口径：`isHosting && status !== 0 && !isClosed && !locked`，
   日报不会再列出这类记录。
2. 「代肝代办」新增第三个视图 **「已结束」**（`view === 'closed'`），列出
   `status === 0 || isClosed(r)` 的全部记录 —— 这些数据仍然存在，只是平时被过滤；
   在这里能打开详情并用「强制删除」清理掉。
3. 若「已结束」里也没有（纯内存残留），重启应用即可消失：列表与下拉现在都从
   `projectsRepo.state` 实时计算，不再持有旧快照。


## 11 · 强制删除 + 重复托管提示

**为什么「删不掉」**：`canHardDelete()` 在「有执行记录」或「被后继项目引用（prevTaskId）」时
返回 false，界面上既没有删除按钮，列表里的删除也会退化成**归档**（并把剩余天数记完）。
两条数据打架时，其中一条就永远清不掉。

**新增 `forceDeleteProject(id, { withHistory = true })`**：

- 删除项目本身；
- `withHistory` 为真时连它的执行记录一起删（`completions`）；
- 清理其它项目对它的引用：`prevTaskId` 指向它 → 置空；`hostingChainId` 指向它 → 挂到自己身上，
  避免删完留下悬空引用。

**界面**：

- 详情窗口在「删不掉」的情况下显示红色「强制删除」（`cfm` 四连点保护，不可恢复）；
- `buildProjectDetail()` 增加 `duplicates`：账号 + 游戏 + 服务三项都相同的其它托管记录
  （含天数 / 是否待激活 / 是否已归档），详情里给一行提示，指明是哪一条在冲突；
- `.pd-btn.danger` 用 `--warn`（红只给删除）。

**测试**：`tests/force-delete.test.mjs`（5 项）——不可普通删除时必须有强制入口、连执行记录一起删、
清理 prevTaskId / hostingChainId、找不到项目时不动其它数据、`withHistory: false` 保留执行记录。

## 14 · 字体统一 + 更强的主题特征 + 行背景色

## 16 · 每日汇报：选中项目后「今日获取资源」没有自动填入（真 bug）

**现象**：在每日汇报里选中一个托管项目，日期与天数会跟着变，但「今日获取资源」还是空项目
（或停在上一个项目的资源行）。

**两个原因**

1. `switchGame()` 会改 `reportGame`，于是 `watch(reportGame)` 在**本轮回调之后**才 flush，
   把资源项按游戏默认值重建了一遍 —— 覆盖掉 `applyTask` 刚刚回填的数值。
   （原来的实现把回填放在 `nextTick` 里，正好躲过这一下；改成同步后被打回。）
2. 同一游戏内换项目时 `reportGame` 没变，watch 不触发 → 资源项与数值都停在上一个项目。

**修法**

- 抽出 `resetResourcesForGame(game, roll)`：按游戏重建默认资源项，**同时把 `roll` 里记录的
  上次「变更后」值填进「变更前」**，并把 `roll` 里出现过的自定义资源（用户自己加的行）补回列表。
- `watch(reportGame)` 里带上当前选中项目的 `roll`（手动切游戏页也能回填）。
- `applyTask()` 里同步重建一次、`nextTick` 再重建一次（幂等），确保不被 watch 覆盖。
- 顺带修掉 `game` 字段的兼容问题：库里既可能存名字（`终末地`）也可能存 id（`endfield`），
  现在两种都认（`gameKeyOfRecord` / `gameNameOfRecord`），否则真实数据里选项目后游戏页不切换，
  任务与资源自然都不会变。

**验证**：预置 `tr-report-roll = { p1: { 嵌晶玉: 1234, 武库配额: 5678, 自定义矿: 99 } }`，
选中项目后资源区得到 `嵌晶玉(变更前 1234) / 武库配额(5678) / 自定义矿(99)`，
且游戏页切到终末地、日期与天数同步为项目真实起止。
## 17 · 回填仍然不生效的真正原因：写入端太窄

上一轮修了「读取时被 watch 覆盖」，但用户的真实数据里**根本没有 `tr-report-roll`**——
在 `%APPDATA%\代肝记录\Local Storage\leveldb` 里搜不到这个键。

原因是写入只发生在 `exportImage()` 成功之后（`commitRoll()`）：
- 用「分享」导出 → 走 `shareImage()`，**从来不写 roll**；
- 填完资源没点导出 → 也不会写。

于是「选中项目 → 自动带出」永远没有数据可读。修法：

1. **填写即记忆**：`watch(resources, …, { deep: true })` + 300ms 防抖，
   把「变更后」（没有变更后就取「变更前」）写进 `tr-report-roll[项目id][资源名]`。
2. **分享导出也提交**：`shareImage()` 成功后调用 `commitRoll()`。
3. 保留上一轮的读取修复：资源项按项目所属游戏重建、回填数值、补回自定义资源行，
   并避免被 `watch(reportGame)` 的默认重建覆盖。

**实测**（seed 数据，项目 p1）：
- 选中项目 → 资源区为「嵌晶玉 / 武库配额」；
- 在第一行「变更后」填 777 → 700ms 后 `tr-report-roll` 变成 `{"p1":{"嵌晶玉":"777"}}`；
- 重新加载并再次选中 p1 → 「变更前」自动带出 `777`。

## 19 · 价格页导出变黑图（真 bug）· 名称列按内容自适应 · 复制到剪切板

### 19.1 导出 PNG 整张 `#161616`

**现象**：加宽到 1080 并追加装饰后点「导出图片」，导出的 PNG 是一整块黑
（卡片、画布空白全是 `R22 G22 B22`）。屏幕上看是正常的，所以只错在导出。

**根因**：把「定位用的小色块」写成了多层 `background-image` ＋
`background-size / background-position` 列表：

```css
background-image:
  /* 网格 2 层 */ ...,
  /* 坐标十字 2 层 */ ...,
  /* lime 角块 ×2、墨色角块 ×1 —— 都是 linear-gradient(90deg, #161616 0 100%) */
  linear-gradient(90deg, #161616 0 100%);
background-size: 24px 24px, ..., 10px 10px, 10px 10px, 6px 6px;
```

html2canvas **不解析 `background-size / background-position` 的列表**，层数一多就
整层回落到 `auto` —— 那条「实心墨色渐变」于是按 100% × 100% 铺满整张画布。

**修法**：定位色块一律改成**绝对定位的真实元素**（`.pr-ef-deco` 里的 `<i>`：
左缘刻度带、坐标十字、三枚角块；卡片里 `.pr-ef-card-deco` 的 `::before/::after`：
右侧刻度 + 左下墨块；卡片头条码改用 `::before` 单层渐变 + 元素自身尺寸）。
`background-image` 只留**平铺纹理**（画布 24px 网格、卡片 45° 斜线），因为
「渐变本身铺满」与 `background-size` 的默认值一致，烘焙不进位置依赖。

**验证**：导出 2160×1082 后逐点读像素 —— 画布 `#f4f4f2`、卡片 `#ffffff`、
顶边三色条 `R255 G0 B240`，不再有黑块。回归断言见
`tests/price-theme.test.mjs`「装饰不用多层 background-image 定位实心色块」。

### 19.2 名称列宽度 = 每张卡片自己的最长名称（不写死百分比）

原先名称列固定 `22%`：短名称（"普托"）那几行留一大片空白，长名称
（"基建毕业（不含矿点）"）又被迫换行，四列读起来是断的。

- 画布外放一把「尺子」`.pr-ef-measure`（`position: fixed; left: -9999px`，
  字体 / 字号 / 字重 / 字距与 `.pr-ef-nm` 完全一致，`white-space: nowrap`；
  用 `fixed` 是为了不撑出滚动条）。
- `measureNameColumn()` **按卡片分别**把所有单项名称量一遍取该卡片的最大值 + 12px，
  逐张写进卡片自己的 `--pr-ef-nm-w`；`.pr-ef-nm { flex: 0 0 var(--pr-ef-nm-w) }`，
  卡片内所有行共用同一宽度（列内对齐），`max-width: 45%` 兜底极端长名称。

> 为什么不是「全局取一个最大值」：单独占满一整行的类别（第一张卡片）名称都很短
> （普托 / 精托 / 全托），全局最大值会把它的名称列撑到 140px，
> 名称与备注之间空出一大截；按卡片各算之后宽卡名称列只有 38px。

- 备注列 `flex: 1 1 auto` 自然吃掉剩余宽度（实测：宽卡 835px、主线卡 305px、基建卡 223px）。
- 数据 / 游戏 / 模式变化时 `watch` 重新量一次；尺子在画布外，不影响导出尺寸。
- 备注短的时候右半边会空，所以从**备注文字到价格**拉一条点线引导
  （`::after` + `border-bottom: 1px dotted`，不用 background-size 平铺）；
  空备注（`.is-empty`）不画点线。

## 20 · 字体：等宽位置保留等宽字体 · 数据列缺字号（真 bug）

### 20.1 把 `--font-mono` 指到正文栈会让字「看起来变大」

一开始为了「所有主题字体都向 P3R 看齐」，把 `--font-mono` 也设成

而字号一个都没改。用户看到的就是「字体没改回来 / 字体很大」。

**定案**：

- `--font-ui` = Bahnschrift + 中文黑体（正文，六套主题共用）；
- `--font-mono` = `"Fira Code", "Cascadia Code", Consolas, "Courier New", monospace`

- 瑞士主题只覆盖 `--font-ui`（Helvetica / Inter），不覆盖 `--font-mono`。

回归断言：`tests/typography.test.mjs`「字体分工：--font-ui 是正文字体栈，

**规则（写进 `theme-swiss.css` 的注释里，也在测试里守住）**

- 文字左对齐，不居中、不两端对齐；分区只用 1px 细线；
- 三种颜色平涂：无渐变底、无投影、无圆角（`border-radius: 0`）；

  行不位移只换不透明度；
