# 第九轮修正 — 六个实际问题（含两个真实计算错误）

> 本轮全部来自真实使用反馈。两个"逻辑错误"（代肝记录金额、续费多一天）都用**你机器上的真实数据**与
> 实际代码跑过确认，不是推测。

## 1. 上一轮的归因错误（先纠正）

上一轮我把「改不了代肝天数」归因成「保存要点 4 次」——**这是错的**。实际是两个逻辑缺陷：

1. `updateProject()` 只在 patch 里带扁平字段 `hostDays` 时才重算计划次数。**详情窗口改的是 `host.startDate/endDate`**，
   走不到这段 → 周期天数变了、`plannedTimes` 仍是旧值 → 界面「执行进度 / 剩余次数」纹丝不动，看起来就像没改成。
2. 减少天数时也可能出现「已完成 > 计划」的不自洽。

因此**保存类按钮已恢复为「连点 4 次」**（与全站写操作一致），不是它的问题。

## 2. 六个问题的修复

| # | 要求 | 修复 |
|---|---|---|
| 1 | 游戏字段按**老数据的方式**（游戏名） | 迁移把 `game` 统一成**游戏名**（id → 名字，名字保持不变）；`createProject` / `updateProject` 也写游戏名。价格表匹配仍走 `gameKey`（id），不受影响 |
| 2 | 改天数「是单纯错误」 | `updateProject()` 改为「**起止日期变了就重算**」`cycleDays` + `plannedTimes`（不少于已完成次数），表单路径与详情窗口路径都覆盖 |
| 3 | 蓝图加备注 + 分组收纳 | 蓝图详情可查看/编辑 `note`，新增表单可填，`BLUEPRINT_FIELDS` 含 `note`（复制会带上）；分组头可点击**收起/展开**组内条目（`▾/▸` + "已收起"提示，纯展示不影响数据） |
| 4 | 代肝记录金额算错 | **真实数据显示**：按执行记录累加 = **9158**，而实际订单总额只有 **1085**（每条记录都带项目的收费快照，同一笔钱被重复算 N 次）。改为只用**订单口径** `revenueStats()`，汇总改为「累计入账」 |
| 5 | 店铺信息可隐藏 | 「数据管理 → 店铺信息」加「在价格表中隐藏」开关（存在独立键 `tr-shop-hidden`，不动既有店铺数据结构）；价格表按开关决定是否渲染店铺信息，切换后立即生效 |
| 6 | 续费多一天 | 根因：`cycleDays` 是**含首尾**的天数（10/12~11/11 = 31），却被直接当作"加多少天" → `addDays(11/11, 31) = 12/12`，比一个自然月多 1 天。改为用**日历跨度**（结束日 − 开始日 = 30）作默认值；服务层、详情窗口、新增记录页三处都改 |
