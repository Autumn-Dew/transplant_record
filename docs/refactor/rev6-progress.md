## 2. 数据模型：一个项目 + 多条收费记录（订单）

```
项目（托管）
  host.startDate / endDate / cycleDays   托管周期（可直接编辑）
  payments: Payment[]                    收费记录（订单）

Payment = { id, amount, paidAt, days, note, createdAt }
   amount   本次收费金额
   paidAt   收费归属日期（收入按它归月）
   days     本次增加的天数
```

* **首次创建托管**即写入第一条订单；此后每次「加天数」追加一条。
* 项目上的 `totalFee / actualFee / paidAt` 表示**最近一次收费**；累计金额一律以 `payments` 为准。
* 编辑详情里的「收费」= 编辑**最近一笔订单**（更早的订单不改写）。
* **老数据天然兼容**：项目没有 `payments` 字段时由 `paymentsOf()` 派生一条只读订单
  （金额 / 收费日 / 周期天数取自项目自身），打开/查看**不会写回**；
  一旦对它「加天数」，派生的一条会随新订单一起落盘为真实记录，历史不丢。

### 收入归月

`revenueStats()` / `incomeByMonth()` / `buildChainSummary().totalIncome` 全部改为
**逐笔收费（订单）展开**：一笔一条、按各自 `paidAt` 归月。
老项目派生的一条金额 = 项目自身金额，因此对历史数据统计结果不变。

## 3. 续费与归档

* **续费**（`addHostingPeriod(projectId, { days, amount, paidAt })`）
  * 结束日整段后移 `days` 天（原结束日之后接 `days` 天：无缝衔接、不重叠、不断档）
  * 周期天数 / 计划次数按新周期重算，已完成次数保留
  * 追加一条收费记录；已完成 / 已到期（含被取消）的项目加天数后重新生效
  * **不新建项目**：`AddPage` 里「同账号已有托管」的确认框已改为「加天数 + 收费」，不再有「独立项目」选项
* **归档**（`archiveProject()`)：把剩余次数全部计入已完成（剩余 = 0）→ 状态置「已完成」→ 打归档标记；
  归档时记下消耗掉的次数，**取消归档**据此精确还原（`restoreProject()`）。
* 归档后不可再确认执行（`confirmExecution` 增加了 `isArchived` 拦截）。

## 6. 兼容性

* 存储键、字段名、分组与执行记录结构均未改动；`payments` 是**可选新增字段**，
  老数据没有它也能正常读写（读时派生，不写回）。
* `hostingChainId` / `prevTaskId` / 连续托管链的 domain 与服务函数**保留**（历史数据与迁移仍需要
  `assignChainIds` / `resolveChainId`），只是**界面不再展示托管链**。
* `renewProject` / `planRenewal` / `pauseProject` / `resumeProject` / `extendProject` / `cancelProject`
  仍在服务层保留（有测试覆盖、可被后续复用），但**界面已不再提供入口**。
