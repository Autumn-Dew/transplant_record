# 蓝图记录编辑优化

> 范围：只做蓝图记录编辑优化（字号 / 颜色 HEX / 以已有蓝图为基础 / 编辑体验）。
> 未开始：返图与价格表的行列式布局、整体动效系统。

## 1. 实测的现状（以实际实现为准）

| 项 | 实际实现 |
|---|---|
| 数据结构 | `blueprintsRepo`（`tr-blueprints`）数组，字段：`id / group / code / name / land / products / source / color` + 任意自定义字段 |
| normalize | `repos.js` 的 `normalizeBlueprints` **只补 `id`**，其余字段 `{...r}` 原样保留 → 新增字段天然兼容、未知字段不丢 |
| 分组 | `blueprintGroupsRepo`（`tr-blueprint-groups`）为**纯字符串数组**，规则：`String(s).trim()` + 去空（不去重） |
| 编辑入口 | ① `BlueprintPage` 详情弹窗（查看/编辑）② `AddPage` 蓝图表单（新增/编辑） |
| 已有能力 | 预设色块 + `<input type="color">` + 预览 + 清除；已有一条「一键补全：选择已有记录」模式（用于任务表单） |
| 缺失 | 记录级字号；颜色无法直接输入 HEX；蓝图无法「以已有蓝图为基础」 |
| 数据同步缺陷 | 删除记录后详情弹窗仍停留在已删除的数据上；分组批量重命名后详情里的组名不更新（保存会把旧组名写回）；`AddPage` 仅在 `onMounted` 同步表单（编辑目标变化时不同步） |

## 2. 实现

### 2.1 纯逻辑层（新增 `src/domain/blueprints.js`）

| 导出 | 作用 |
|---|---|
| `FONT_SIZE_MIN/MAX = 8/48`、`DEFAULT_FONT_SIZE = 12` | 与蓝图列表 `.bp-col` 的既有字号一致 → **未设置字号的记录外观与改动前完全相同** |
| `FONT_SIZE_PRESETS = [11,12,13,14,16,18,20]` | 常用字号快捷选项 |
| `normalizeFontSize(v)` | 空 / 非数字 / **非正数** → 默认值；越界夹紧；小数取整 |
| `fontSizeOf(record)` | 纯读取：未设置 → 默认值，**不写入记录** |
| `isValidFontSize(v)` | 界面提示用（不抛错） |
| `isValidHex(v)` / `normalizeHex(v)` | HEX 校验与规范化（`#` 可省略，自动补全；非法值原样返回由界面提示，**不静默丢弃**） |
| `blueprintCopy(record)` | 深拷贝内容与配置（去掉 id） |
| `duplicateBlueprint(record)` | 生成**完全独立**的新蓝图（新 id） |

### 2.2 界面（两处都改）

| 位置 | 变更 |
|---|---|
| `BlueprintPage` 列表 | 名称列按 `fontSizeOf(row.item)` 渲染 → 字号可见、可预览 |
| `BlueprintPage` 详情 | 颜色增加 **HEX 直填**（非法值红框提示）；新增**字号**行（常用选项 + 数字输入 + 实时预览）；查看态新增「以此为基础新建」 |
| `AddPage` 蓝图表单 | 新增「从已有选择」（仅新增时）→ 复制为独立草稿；颜色 HEX 直填；字号行（常用选项 + 数字输入 + 预览） |

### 2.3 数据同步修复（§7）

1. **删除记录后**：若详情正打开着同一条 → 自动关闭，不再停留在已删除的数据上。
2. **分组批量重命名后**：若详情打开着组内记录 → 从 repository 重新取最新记录，组名同步（否则稍后保存会把旧组名写回）。
3. **保存后**：详情立即从 repository 刷新（不再停留在旧副本上）。
4. **`AddPage`**：`onMounted` 改成 `watch([editRecord, editType])` → 编辑目标变化时表单同步，不残留上一条数据。
5. **落库前规范化**：`fontSize` / `color` 保存时规范化 → 空值与越界值不会写进记录。

## 3. 兼容性（§6）

* `fontSize` 是**新增的可选字段**：旧记录没有它 → 读取用默认值显示，**不会因打开/查看而被写入**（有测试断言）。
* 蓝图仓库的 normalize 只补 `id`、其余字段原样保留 → 历史字段不被改写，自定义字段不丢。
* **存储键、业务关系、分组数据结构均未改动**（`blueprintGroups` 仍是纯字符串数组；纯逻辑层不导入 repository）。
* 部分字段更新（`update`）不会覆盖丢字号 / 颜色 / 自定义字段（有测试断言）。
