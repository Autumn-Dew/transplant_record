# 业务流程（Phase 2 之后）

## 1. 单次项目

```
新增（选择游戏 / 服务 / 计划日期）
  └→ 项目 state=pending，plannedDate=今天（或指定日期）
      └→ 出现在「今日代办」（计划日期 <= 今天时）
          ├→ 完成   → 生成执行记录（done）    → 项目 state=completed
          ├→ 跳过   → 生成执行记录（skipped） → 项目保持 pending，改日再出现
          ├→ 异常   → 生成执行记录（abnormal）
          ├→ 延期   → 只改 plannedDate，不产生记录
          └→ 取消   → 项目 state=cancelled（不再生成代办）
```

## 2. 托管项目

```
新增（游戏 / 服务 / 托管起止日期 / 执行计划 / 计划次数）
  └→ 项目 state=active，host{startDate,endDate,plan,plannedTimes,completedTimes}
      └→ 每天按 host.plan 自动生成「今日代办」（不落库，实时派生）
          ├→ 完成    → 生成执行记录 → completedTimes+1 → 次数用尽则 state=completed
          ├→ 跳过    → 记录 skipped → 不计入已完成次数
          ├→ 异常    → 记录 abnormal
          ├→ 延期    → 该日写入 host.skippedDates（不生成代办、不产生记录）
          └→ 暂停/恢复/取消/延期（改 endDate）/归档
```

**关键约束**：托管周期（`startDate`~`endDate`、`cycleDays`）与实际执行次数
（`completedTimes` / `plannedTimes`）完全分离；项目状态、代办状态、执行记录结果三者互不混用。

## 3. 续期（加天数 + 收费）

```
客户继续托管（同一个客户 / 同一个项目）
  └→ 新增同账号托管时检测到「已有托管项目」→ 弹出确认（天数默认取原周期天数，可改）
      └→ 确认：在原项目上加天数（结束日顺延、周期天数与计划次数重算）
               + 追加一条收费记录（金额 / 收费归属日）→ 收入按每笔收费归月
               项目资料、执行记录与已有订单都不变；**不新建项目**
```

> 历史数据里「每次续费 = 一个独立项目」的形态（`prevTaskId` / `hostingChainId`）仍可正常读取，
> 只是界面不再新建这类项目，也不再展示托管链。

## 4. 历史与归档

* 执行记录一旦生成即独立保存；项目改名 / 改价 / 归档 / 续期都不会改写它。
* 每条记录保留生成时的快照：游戏名、服务内容、价格、账号、执行结果、计划日期与实际完成日期。
* 删除项目时：有执行记录或有后继项目 → **只能归档**（保留历史关联）；无任何引用才物理删除。
* 归档 = **消耗全部剩余天数、直接完成整个托管**（并打 `archivedAt` 标记）；
  「取消归档」会精确还回被消耗的天数。

## 5. 游戏与服务项目

```
游戏管理入口：数据管理 →「游戏与服务」分类（原独立页面与导航入口已移除）
新增游戏（不限数量）→ 配置服务项目（名称/默认价/单位/备注/排序/启用）
  ├→ 创建项目、列表筛选、统计、价格一览、数据管理自动获得该游戏
  ├→ 改名不影响历史记录（记录保存的是当时的名称快照）
  ├→ 停用：不再出现在可用列表，历史与既有项目不受影响
  └→ 删除：有项目引用则拒绝，改为归档
游戏不使用图标：不提供图标选择 / 展示 / 占位；旧数据里已有的 icon 仅原样透传，界面不再使用。
```

## 6. 数据迁移

启动时（Vue 挂载前）自动执行：备份原始数据 → 增量补齐 v2 字段 → 记录数据版本。
幂等、可重复执行、可回滚（`services/migration.js` 的 `rollback()`）。
