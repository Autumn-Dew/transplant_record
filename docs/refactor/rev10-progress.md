# 第十轮修正 — 六条使用反馈

## 1. 修改托管天数「少一天」——实测未复现，已加自动校验

按要求**不猜、实测**。用真实 UI（Electron 冒烟）走了一遍：详情窗口 → 编辑 → 把「托管天数」改成 20 → 保存，结果：

```
详情显示：{"start":"2026-10-09","end":"2026-10-28","days":"20 天","progress":"0 / 20 次"}
```

* 周期天数 = **20 天**（不是 19）
* 结束日 = 开始日 + **19** 天（因为天数**含首尾**：10/09 与 10/28 各算一天）
* 计划次数同步为 20

服务层探针也把每条路径都跑了一遍（新建 / 表单扁平 hostDays / 详情整份 host / 只改结束日 / 递增与递减），结果一致：**填 N 天就是 N 天**。

因此更可能是**口径差异**：系统的约定是「结束日 = 开始日 + 天数 − 1」（与「托管天数留空 = 1 天」一致）。
如果你期望的是「结束日 = 开始日 + 天数」（不含首尾），告诉我，我改成那个口径（会连带调整「留空 = 1 天」这条约定）。

已把这条固化为冒烟断言：改 20 天后，详情里的托管天数必须是 20、结束日必须是开始日 + 19 天、计划次数必须是 20。

## 6. 代肝记录的时间排序

**原因**：旧排序无论选「时间 / 金额 / 游戏」，都先把 `wasHosting` 的记录整体推到最前，时间顺序被打乱。
**修复**：按所选维度纯粹排序（金额 → fee 倒序、游戏 → 名称、时间 → 「完成日期 + 时间」倒序，完全相同时用 id 兜底保证稳定），不再按类型分组。
