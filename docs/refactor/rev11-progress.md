# 第十一轮修正 — 用真实数据体检 + 五条反馈

## 1. 托管天数只能减少，不能增加

增加天数必须走「续费」（加天数 + 记一笔收费），所以「改天数」被限制为**只能减**，三处都封顶：

* `projectService.updateProject`：按原周期天数封顶（绕过 UI 也改不长）
* 项目详情窗口：输入框 `max` = 原天数，提交时再 `Math.min` 兜一层
* 新增记录页（编辑态）：同样按原天数封顶

已验证：真实数据 14 个托管项目改成 20 天全部成功；把天数改成 999 被拒绝（结束日不变）。

## 2. 代肝记录只显示「已完成」

跳过 / 异常 / 取消都是托管中途操作，不再进入代肝记录列表，统计（总记录 / 已完成）也只按完成记录算。
当前数据 118 条记录全部是 `done`，所以暂时看不出差别，但逻辑已生效。

## 3. 「备份全部数据」移到设置页

从「数据管理」移到「设置 → 备份数据」：导出一个带日期的 JSON 文件（含全部 `tr-` 键，不含迁移备份），文件内附还原说明。
数据管理页不再有备份入口。

## 4. 蓝图记录：备注列 + 默认只展开第一组

* 列表第 4 列由「蓝图来源」改为「备注」（显示 `note`）
* 分组默认**只展开第一个组**，其余收起（共 12 个分组，全展开太长）

## 5. 用真实数据体检项目逻辑

对 `testdata/` 的 72 个项目 / 118 条记录 / 3 个游戏 / 68 个蓝图做了完整体检，**发现一个真问题**：

### 发现的 Bug：托管周期天数与结束日不一致（6 个项目）

```
项目 1   2026-10-09 → 2026-11-09   含首尾 32 天，但 cycleDays = 31
项目 2   2026-10-12 → 2026-11-12   含首尾 32 天，但 cycleDays = 31
项目 3   2026-10-07 → 2026-11-07   含首尾 32 天，但 cycleDays = 31
项目 4   2026-10-01 → 2026-11-01   含首尾 32 天，但 cycleDays = 31
项目 5   2026-10-01 → 2026-11-01   含首尾 32 天，但 cycleDays = 31
项目 6   2026-09-24 → 2026-10-24   含首尾 31 天，但 cycleDays = 30
```

**根因**：这些项目的结束日是按「开始日 + 1 个月」写进去的，而天数按另一种口径记，两者差一天。
用户一改天数，系统按天数重算结束日，结束日就「退回」正确值 —— **看起来就像"少了一天"**。

**修法**：`normalizeHost` 改为**以天数（cycleDays）为准**，结束日必须等于「开始日 + 天数 − 1」。
所以上面的项目结束日会被校正一天（如 11-09 → 11-08，仍是 31 天）。

> ⚠ 这是唯一会改动既有数据的修正：6 个托管项目的**结束日提前 1 天**，天数、已完成次数、收费记录都不变。
> 如果你更希望「保留结束日、把天数 +1」，告诉我改回去。
